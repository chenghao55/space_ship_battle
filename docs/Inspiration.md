# Kpop Universe - Overview.md

> 本文件是給老師、組員與展示觀眾閱讀的遊戲總覽。  
> 本版本由原本《Orbital Hunter / Gravity Drift》的太空引力漂移概念改造而來，保留原本的 2.5D 太空飛行、行星引力、Boost、雷達、鏡頭與科幻 UI，但核心玩法改為「限時救援女團成員」。

---

## 一、專案定位

《Kpop Universe》是一款使用 JavaFX 製作的 2.5D 太空救援遊戲。

玩家駕駛太空飛船，在固定大小的星系地圖中，依靠行星引力、重力彈弓、飛船慣性、Boost 加速、聲音辨位與雙層雷達，在 180 秒內尋找並救援散落在各星球附近的女團成員。

遊戲的重點不是大型宇宙探索，而是一個短時間、高回饋、可展示的完整關卡：

```text
開始任務 → 180 秒倒數 → 聲音與雷達找人 → 救援成員 → 避開敵人 → 保持 HP → 最後救援觸發短暫停格 → 結算評級
```

---

## 二、與原始 Inspiration.mdc 的關係

原始 Inspiration.mdc 的核心是：

- 太空漂移感
- 引力彈弓
- 行星作為地形
- 雷達探索
- Boost 加速
- 高速甩尾
- 科幻 HUD
- 第三人稱追尾鏡頭

新版不刪除這些設計，而是將「摧毀敵方據點」改成「救援女團成員」。

也就是說：

| 原始設計 | 新版 Kpop Universe |
|---|---|
| 找敵方據點 | 找散落在星球附近的女團成員 |
| 摧毀核心 | 觸碰並救援成員 |
| 雷達追蹤據點訊號 | 雷達與歌聲追蹤成員 |
| 戰鬥破壞感 | 救援與保護隊伍感 |
| 據點爆炸結算 | 最後救援停格 + 結算評級 |
| 漂移加分 | 漂移仍保留為操作與展示亮點 |

---

## 三、遊戲目標

關卡開始後啟動 180 秒嚴格倒數。  
玩家需要在時間內盡可能救援所有女團成員，並維持飛船 HP 大於 0。

勝利與評級不只看救援人數，也看剩餘血量、最後仍在隊伍上的救援單位，以及擊敗敵人數量。

---

## 四、評分與評級系統

滿血為 5 顆心。  
最終評級改為總分制，綜合救援成功率、最後仍在隊伍上的救援單位、擊敗敵人數量與 HP 狀態。

若飛船 HP 歸 0，不再必然 F；只會扣分。完全沒有救援、擊殺或存活成果時才容易落入 F。

| 評級 | 條件 |
|---|---|
| S | totalScore 95-100 |
| A | totalScore 80-94 |
| B | totalScore 60-79 |
| C | totalScore 20-59 |
| F | totalScore 0-19 |

結算畫面必須讀取真實遊戲資料，不可使用假數據。

總分：

```text
rescueScore = rescueRate * 60
aliveScore = min(aliveRescuedCount * 5, 25)
killScore = min(enemyKillCount * 3, 15)
HP <= 0 扣 20；HP = 1 扣 8；HP = 2 扣 4；HP >= 3 不扣
totalScore clamp 0..100
```

## 五、完整遊戲流程

```text
主選單
  ├─ Credits → 獨立 Credits Screen，可用 Back 或 ESC 回主選單
  ↓
開始任務
  ↓
180 秒倒數開始
  ↓
玩家利用外圈雷達與歌聲尋找女團成員
  ↓
角色牌從開局就可見；玩家靠近時雷達與歌聲變強
  ↓
玩家用飛船本體或後方隊伍碰到成員，完成救援
  ↓
成員加入飛船隊伍，頭像出現在 UI
  ↓
敵人與子彈干擾玩家
  ↓
玩家被擊中時扣 HP，並永久流失最後救援的成員
  ↓
救到最後一名可救援成員時觸發 0.15 秒停格
  ↓
淡出進入結算畫面
```

## 六、玩家飛船設計

玩家操控一架太空戰機。

### 操作

| 操作 | 功能 |
|---|---|
| WASD / 方向鍵 | 控制飛船移動方向 |
| Shift | Boost 加速 |
| E / 滑鼠左鍵 | 射擊敵人或防禦裝置 |
| 雷達觀察 | 尋找敵人、子彈與成員方向 |
| 聲音辨位 | 依歌聲音量與聲波 UI 找到目標 |

### 飛船特性

1. **HP 系統**  
   飛船滿血為 5 顆心，被敵人子彈或敵人碰撞擊中時扣 1 顆心。

2. **Inertia Surfing**  
   飛船受慣性影響，不會立即停止或轉向，呈現太空滑行感。

3. **Boost 加速**  
   Boost 是有限資源，用於高速移動、逃離危險、貼近行星甩尾。
   飛船速度必須有明確上下限：最低巡航速度約等於按住 W 推進 1 秒後可達到的速度；最高速度約等於從最低巡航速度再按住 W + Boost 1 秒後可達到的速度。這讓玩家不會慢到失去操作感，也不會因 Boost 或重力彈弓無限制暴衝。
   Boost 時鏡頭可有輕微 FOV 拉伸 / 畫面縮小感，但不得過度明顯；重點是提示速度感，而不是讓玩家視野大幅跳動。

4. **Drift Mechanics**  
   飄移與旋轉不以機鼻為中心，而是偏向飛船尾部或一角作為視覺軸心，讓轉向更像高速甩尾。
   飛船方向只由鍵盤方向輸入、速度與物理狀態影響；滑鼠移動不改變飛船左右方向，滑鼠只保留射擊等按鍵用途。
   A / D 左右轉向角速度改為上一版目前值的一半，讓飛船轉向更穩、更有太空慣性感。

5. **尾翼與殘影特效**  
   只有在按下 Shift 或觸發大角度飄移時，尾翼才會產生強烈推進與殘影。

6. **Snake Hitbox**  
   飛船本體與已救援成員形成一條隊伍。  
   只要飛船或隊伍任何一處碰到未救援成員，即救援成功。  
   但敵人子彈打到飛船本體或後方隊伍，也都算玩家受傷。

## 七、女團成員 Idol 系統

### 1. 群集生成

一個星球對應一個女團。  
每個星球可在其引力圈、軌道或周邊星塵中生成多名該團成員。

新版明確規則：要救援的歌手不是生成在行星內部，也不能被行星球體遮住。  
每位 Idol 都是環繞行星運動的軌道物體，位於行星半徑之外的安全軌道帶上，會以自己的軌道半徑、初始角度與角速度繞母行星移動。

現況盤點：程式已經有 8 顆非恆星行星，行星使用 `src/main/resources/photo` 的女團 logo texture，音樂使用 `src/main/resources/pop_musics` 的多首歌曲；原先的球形救援目標已改為個別成員 portrait 的直立式全息 billboard。

新版視覺規格：救援目標不再是球體、厚重橢球、普通卡牌或 UI 卡片。  
每位 Idol / RescueUnit 必須是一個面向鏡頭的直立式人物紙片人 / 全身立牌，像韓團成員的透明背景立牌漂浮在太空中等待救援。  
人物圖片本身就是主體 texture，必須保持原比例，不可橫向拉寬或壓扁；若圖片有透明背景，必須保留 alpha，不再把人物塞進方形卡牌或厚面板裡。  
紙片人可以有很薄的厚度暗示、淡淡發光外框與小型 group logo badge，但不得重新變成普通長方形卡牌。
每個 Idol 生成時必須立刻建立世界中的 view，並由 LevelManager / GameManager 加入 worldRoot。不能只在救援後顯示 UI 牌子。
救援單位不需要隱藏，也不需要進入任何範圍才顯示。所有 Idol 從遊戲開始就是 AVAILABLE 狀態，世界場景中必須清楚顯示完整全息立牌，並持續環繞對應行星運動。
全息立牌必須永遠面向飛機螢幕畫面，不管玩家從哪個方向接近，都應盡量看到人物圖片正面。
世界中的救援單位不可再使用小型水平 marker、圓點、方形卡牌或類似子彈 / 敵人圖示的顯示方式；UI 底部牌子可保留，但 world object 必須是主要可見的人物紙片立牌。
程式實作上，世界中的 Idol view 以 JavaFX `ImageView` 顯示人物 texture 並保留透明背景，再搭配發光外框、group logo badge、唱歌 pulse 與 rescued trail；不可用厚 Box 卡牌本體或單純 UI card 取代。世界中的人物紙片立牌大小改為目前的 2 倍，仍保留人物可讀性；這只影響宇宙世界物件，不改變左下角 HUD 已救援牌子的顯示大小。
救援立牌是世界中的實體阻擋 / 可被遮擋單位，渲染時要參與 JavaFX 3D depth buffer；它不能永遠蓋在行星、敵人或其他世界物件上方。
每個未救援 Idol 和所屬行星表面的距離改成上一版目前距離的 1/2，讓救援牌更貼近母行星環繞。
救援牌環繞行星時，軌道位置必須對齊全息立牌的中心點，而不是立牌底部或底座，讓角色牌像真正的衛星物體沿軌道運動。
救援單位世界視覺尺寸放大後，救援吸引半徑、隊伍跟隨間距與隊伍 hitbox 也要同步放大；左下角 HUD 牌子尺寸獨立管理，不跟著世界立牌大小變動。
遊戲啟動後需要輸出 rescue unit debug log，檢查每顆 Planet 的 groupId、成員數、每個 Idol 的 parentPlanet、orbitRadius、orbitAngle、texturePath、view 是否加入 worldRoot、visible、opacity 與 position。

資料來源以集中式 GroupConfig 為準：

| groupId | musicFile | planetTexture | memberCount | portrait prefix |
|---|---|---|---:|---|
| nmixx | bluevalentine.MP3 | nmixx.jpg | 6 | nmixx |
| itzy | cake.MP3 | e.jpg | 4 | itzy |
| ive | iam.MP3 | ive.jpg | 2 | ive |
| aespa | supernova.mp3 | a.jpg | 4 | aespa |
| twice | thisisfor.MP3 | twice.jpg | 4 | twice |
| lesserafim | spaghetti.MP3 | lesserafim.jpg | 6 | lesserafim |
| babymonster | drip.MP3 | babymonster.jpg | 5 | babymonster |
| blackpink | dududu.MP3 | blackpink.jpg | 4 | blackpink |

成員圖片位於 `src/main/resources/IdolPic`，命名支援 `prefix + index`，副檔名支援 png / jpg / jpeg，例如 `nmixx1.png`、`twice4.jpg`。若個別圖片不存在，fallback 到該團 logo；若 logo 也不存在，使用 placeholder。
每顆 Planet 必須管理自己的救援單位清單，讓 nmixx 星球持有 6 位 nmixx 成員、itzy 星球持有 4 位 itzy 成員，以此類推。

例如：

```text
nmixx 星球 → 6 名成員，使用 nmixx1 ~ nmixx6 portrait
twice 星球 → 4 名成員，使用 twice1 ~ twice4 portrait
blackpink 星球 → 4 名成員，使用 blackpink1 ~ blackpink4 portrait
```

### 2. 顯示與救援

每位 Idol 一開始就是可見的 AVAILABLE 狀態。  
玩家不需要先偵測，進入救援吸引範圍後即可救援。雷達與音樂仍可依距離變強，但不可控制 Idol 是否顯示。

### 3. 音量與距離

距離越近，音量越大。  
設計概念：

```text
每靠近 Idol 5 單位，聲音大小 +5
```

### 4. 同團音樂防重疊

為避免同一女團多名成員同時造成同一首歌多軌重疊，系統對每個女團只播放「距離玩家最近的那一位未救援成員」的歌聲。

也就是：

```text
同一女團多名 Idol 靠近玩家 → 只取最近者計算音量
不同女團同時靠近玩家 → 可同時聽到多首歌
```

### 5. 登船與伴唱

救援成功後，該 Idol 會加入飛船隊伍。  
UI 顯示該成員頭像。

航行期間，已救援成員會隨機開口唱歌。  
唱歌時，該成員 UI 頭像發光。

### 6. 受擊永久流失

玩家被敵人擊中時：

1. HP 扣 1。
2. 觸發強烈畫面震動。
3. 若隊伍中有已救援 Idol，最後救援的 Idol 被撞飛。
4. 該 Idol 播放「啊啊啊啊~~~」語音。
5. 撞飛後化為星塵消失或飛出畫面。
6. 該 Idol 無法再次救援。
7. 玩家本局最高可救援人數永久減少，評級會受到影響。

這讓救援不只是收集，也包含保護隊伍的壓力。

## 八、行星與場景

行星仍保留原本設計：不是背景，而是地形與玩法機關。

### 行星功能

1. 具有 3D 立體外觀。
2. 可使用女團 Logo 或主題視覺。
3. 每顆行星內部管理其對應女團成員清單。
4. 提供引力與重力彈弓效果，讓玩家能利用行星切線加速。
5. 提供碰撞推出力場，避免玩家卡進星球內部。
6. 可作為敵人、成員與路線規劃的空間參考。

### 行星公轉

除中央恆星外，所有行星都必須以恆星為中心慢慢公轉。  
展示版的每顆行星公轉半徑都必須比目前版本更大，而且每顆行星之間的公轉半徑要有明顯差異。  
公轉速度要慢，讓玩家能看出星系在動，但不能快到影響救援可讀性。  
半徑配置要避免多顆行星在同一圈上，看起來應該像層次清楚的多軌道星系。

### 行星公轉避讓

當兩顆行星距離低於安全距離時，軌道位置較後方的行星會暫停公轉。  
暫停期間行星仍會自轉、保留碰撞與救援配置，只是不沿軌道前進。  
直到兩顆行星距離重新大於恢復距離，暫停行星才重新公轉。

### 行星配置

目前展示版已配置 1 顆中央恆星與 8 顆女團行星。  
8 顆女團行星使用 `GroupConfig.defaults()` 的 nmixx、itzy、ive、aespa、twice、lesserafim、babymonster、blackpink，半徑、質量、初始角度與公轉半徑皆不同，形成清楚的多層星系結構。  
每顆女團行星都配置：

```text
一組待救援 Idol
同星球 Idol 使用該 group 的成員人物圖；行星本體使用該 group logo texture
多座敵方衛星砲塔守衛
慢速公轉
```

### 重力彈弓飛行規則

飛船會再次受到行星與恆星的吸引力、切線加速與重力彈弓影響。  
玩家移動由自身推進、Boost、慣性、星體引力、阻力與邊界回推共同形成。  
行星仍然可以作為碰撞地形；飛船碰撞星體時會扣血並被推出表面。
本版重力彈弓要大幅降低引力與加速度，保留漂移牽引感，但不得把飛船強烈吸向行星或產生過猛加速。

### 初始分布與玩家出生點

所有行星的初始位置應盡量均勻分散環繞恆星，不要隨機擠在同一側或彼此太近。  
遊戲開始時，飛船要放在一個附近沒有敵方攻擊單位的安全空域，並且前方能直接看到完整恆星，讓玩家一進場就理解星系中心位置。

### 飛船撞行星

飛船接觸行星表面或近表面碰撞圈時不會直接死亡，但必須扣 1 顆心。  
撞擊後飛船會被排斥力場推出行星表面，並有短暫無敵時間，避免同一次碰撞在同一秒內連續扣血。

### 航道邊界

地圖具有固定大小。  
偏離軌道 / 脫離航道的判定範圍改為上一版的 1.5 倍，讓玩家有更大的操作空間與引力彈弓緩衝區。  
飛船初始位置放在接近偏離軌道範圍的位置，但鏡頭仍需能完整看見中央恆星，且附近不得有攻擊單位。
當飛船超出畫布邊界時，不直接死亡，而是：

```text
顯示「你已脫離航道！」
給予減速阻力或回推力
```

## 九、敵人與子彈

敵人以靜態砲台為主，另有多個分散擺放的移動型追蹤單位。展示版敵方單位數量要有壓力，但砲台型敵人數量改為上一版目前配置的一半，讓路線壓力下降但仍保留戰鬥存在感。

### 敵人屬性

- 固定位置或小範圍巡邏。
- 擁有中距離 Aggro Zone，玩家靠近戰區時才開火，避免全地圖追擊。
- 擁有 HP，例如 3 點生命值。
- 玩家進入範圍後射擊，且會依玩家速度預判瞄準。
- 敵人射擊間隔比上一版延長 1 秒，讓彈幕壓力下降。
- 敵人子彈速度較快，精準度高，但仍保留少量誤差讓玩家可以靠 Boost、行星掩護與漂移躲避。
- 敵人必須使用 JavaFX primitive shapes 建立程序化 3D 模型，不依賴 OBJ 或外部模型檔。
- 敵人外觀是科幻浮空衛星砲塔：發光 Sphere 核心、旋轉外圈與四向砲管。
- 不顯示敵方單位的 Aggro 領域，避免畫面被大型範圍提示蓋住。
- 射擊前核心短暫變亮，射擊瞬間砲口 flash；被擊中時閃紅或閃白；HP 歸零時播放明顯爆炸後移除。
- 敵方砲台總數為上一版的一半；目前展示版 8 顆女團行星合計約 12 座砲台，使用每顆 1~2 座的方式分散配置。
- 砲台型敵人與移動型敵人的程序化模型目前使用 `EnemyView.MODEL_SCALE = 4.0 / 3.0`，保留可辨識度並避免回到過大的模型遮擋。
- 所有敵人位置要重新配置並大幅散開，不要緊貼成團；砲台與移動型敵人都要分布在較寬的行星外側防線上。
- 玩家子彈有效距離只應略長於敵人射程，讓玩家需要接近戰區才能清除砲塔，不可再用超遠距離安全掃射。
- 移動型敵人建模與砲台相似，但中央核心改成綠色。
- 移動型敵人是快速攔截單位，建模與砲台相似但中央核心為綠色。
- 移動型敵人的偵測 / 攻擊半徑目前為砲台型敵人射程的 6 倍。偵測到飛機後會快速飛向飛機當前視角 / 機頭方向的前方攔截點，維持一段前方壓迫距離並開始攻擊。
- 移動型敵人的攻擊頻率是目前移動型敵人設定的 1.5 倍；HP、預判射擊、受擊與爆炸邏輯仍和砲台一致。
- 移動型敵人數量調整為前一版配置的 4 倍，且每隻必須分散擺放，不可集中在同一顆星球附近。
- 所有敵人死亡時都必須有明顯爆炸視覺特效，包含高亮 flash、碎片外散與整體淡出；死亡 flash 的視覺半徑必須比目前版本大 5 倍。

### 敵人死亡爆炸流程

敵人 HP <= 0 時不可直接消失，而是進入死亡流程：

```text
最後一擊閃白 / 閃紅 0.08~0.12 秒
主爆炸能量 Flash 擴張 0.25~0.4 秒
震波環沿遊戲平面向外擴散
8~16 個碎片粒子向四周飛散 0.5~1.0 秒
0.1~0.2 秒後出現 2~3 個小型二次爆光
距離玩家越近，Camera Shake 稍微越強
特效播放完畢後才移除敵人
```

音效使用 `AudioSystem.playSfx("enemy_destroy")` 與 `AudioSystem.playSfx("explosion_small")` 介面；若音效檔不存在，不可讓程式崩潰。

### 玩家消滅敵人方式

1. **射擊消滅**  
   玩家子彈打中敵人，敵人 HP -1。  
   敵人 HP <= 0 後爆炸並移除。

2. **碰撞消滅**  
   飛船本體或後方隊伍撞到敵人也可以消滅敵人。  
   但這是危險行為，會同時觸發玩家受傷判定。

### 玩家受傷條件

以下情況皆算受傷：

- 敵方子彈打中飛船本體。
- 敵方子彈打中後方 Idol 隊伍。
- 飛船本體撞到敵人。
- 後方 Idol 隊伍撞到敵人。

受傷效果：

```text
HP -1
Camera Shake
最後救援 Idol 永久流失
```

### 子彈撞行星或恆星

不論玩家子彈或敵人子彈，碰到行星或恆星地形時不可反彈。  
正確行為：

```text
子彈碰到行星 / 恆星 → 火花特效 → 子彈消失
```

這個判定必須發生在物理排斥力之前；子彈一旦接觸行星半徑，就標記為死亡並從場景移除，不能被行星力場推開或繼續飛行。

### 恆星外觀

中央恆星必須是不透明、非常明亮的發光球體。  
主色調必須是暖色橘色。  
它可以使用自發光材質或高亮材質，但不可半透明、不可暗沉，且仍然作為子彈碰撞會消失的地形。

### 子彈與排斥力場

子彈不是飛船，不可受到行星或恆星的排斥力場、引力彈弓或危險區推力影響。  
物理層必須先對子彈本幀飛行線段做碰撞掃描；只要線段碰到行星或恆星半徑，子彈立即消失。  
若沒有碰撞，子彈只沿自身速度直線前進，不可被 `dangerRadius` 彈開。

## 十、雙層雷達系統

### 1. 內圈：危險警告雷達

內圈是實線圓形雷達。

當敵人或子彈進入危險範圍時，內圈對應方向亮紅光。

用途：

- 提醒敵人方向。
- 提醒敵方子彈來向。
- 高速飛行時提供危險感知。

### 2. 外圈：歌手探測雷達

外圈是向外擴散的脈衝波紋，參考《薩爾達傳說：曠野之息》的神廟雷達。

距離最近目標 Idol 越近：

- 波紋擴散速度越快。
- 振幅越大。
- 聲音提示越明顯。

### 3. 防呆提示

玩家太久找不到目標時，系統播放提示音，並可短暫加強脈衝雷達強度，引導玩家回到正確方向。

## 十二、音效與音樂

音效是核心玩法的一部分。

### 音效設計

1. **Ambient Base Track**  
   宇宙環境底層音樂，例如低音節拍或心跳聲。

2. **K-Pop 歌聲提示**  
   玩家接近 Idol 時，對應女團歌曲漸漸變大。

   每個 IdolGroup 由 GroupConfig 綁定固定歌曲，例如 nmixx 使用 `bluevalentine.MP3`、itzy 使用 `cake.MP3`、aespa 使用 `supernova.mp3`。

   對應成員的音樂音量必須與當下外圈雷達脈衝 / 震動強度等比改變。  
   越接近該團最近未救援 Idol，雷達震動越強，該團歌曲音量也越大；距離遠時音量降低。

   音量必須是更明顯的線性關係：雷達完全沒有感測到 Idol 時，對應歌曲音量為 0 並停止播放；進入雷達感測範圍後，依距離線性增加音量，越靠近越大聲。

3. **環境音自動淡出**  
   當玩家靠近 Idol，K-Pop 歌曲變大時，環境音樂自動 Fade-out，讓聲音焦點轉向歌手。

4. **多女團混音**  
   不同女團可同時發聲，但同一女團只播放最近成員，避免 Echo Bug。

5. **流失語音**  
   Idol 被擊飛時播放「啊啊啊啊~~~」。

6. **戰鬥與危險音效**  
   包含射擊、受擊、Boost、行星危險、警告提示等。

## 十三、Ending Freeze 結算演出

當玩家碰到最後一名可救援 Idol，達成勝利條件時，不立刻切畫面。

系統會進入結束停格：

```text
ENDING_FREEZE 0.15 秒停格
播放 impact 音效
不再進入結算前 Bullet Time
直接淡出到獨立 Result Screen
Result Screen 讀取 ScoreResult，依序跳動顯示 rescued / total、rescueRate、aliveRescuedCount、lostRescueCount、enemyKillCount、playerHp、totalScore
所有數字完成後延遲 0.3 秒顯示 Rating
```

這是展示時的重要視覺亮點。

- Result 數字跳動播放 tick sfx，但限制每 0.04~0.08 秒一次，不能每幀播放。
